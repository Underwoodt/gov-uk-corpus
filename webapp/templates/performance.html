How to read this table — what each figure means

Every measure is shown as a Total for the run with indented Phase 1 – Inclusion and Phase 2 – Exclusion rows beneath it. Runs are stored one row per phase in evaluation_runs; the figures below combine a run's two phases.

MeasureWhat it meansHow it's calculated
Model · Phase 1/2The model that actually served each phase.provider / actual_model (the model the API reported, which can differ from the one requested).
Total EvaluationsPages scored across both phases.Sum of each phase's pages. Inclusion scores the whole shortlist; exclusion re-scores only the pages inclusion kept.
Total Evaluation CostMoney spent on the run.Sum of each phase's cost (USD), priced per model from its input/output tokens.
Average Evaluation Cost (per 100)Cost to score 100 pages.total cost ÷ total pages × 100.
Average LLM latency per callTypical model wait for one page.total LLM wait ÷ total pages (i.e. mean of the per-page round-trips).
Total Input TokensPrompt tokens sent to the model.Sum of in_tokens = cache hit + cache miss.
  of which cache hit / missInput tokens served from / not from the prompt cache.hit_tokens / miss_tokens. Hits are far cheaper — high hits mean caching is working.
Total Output TokensTokens the model generated (the JSON verdicts).Sum of out_tokens.
Total LLM wait (sum of calls)All the model waiting, added up — not real time.Sum of each page's measured round-trip (total_ms). Unaffected by concurrency.
Total wall-clock timeReal elapsed time, start to finish.Per phase: finished_at − started_at; the total sums the phases. With concurrency this falls well below the LLM-wait figure (calls overlap).
Decisions KeptThe run's final shortlist size.The last phase's kept (exclusion if it ran, else inclusion). Phase rows show each phase's own kept.
Decisions DroppedPages the run removed.Sum of each phase's dropped (inclusion + exclusion).
Decisions disagree with Run 1How differently this run judged vs the baseline (Run 1).Over the pages both runs scored (same URL), the count where the keep/drop verdict differs — compared per phase (inclusion vs inclusion, exclusion vs exclusion). ≈ 0 means they agreed. Run 1 shows “—” — it's the baseline, so it can't disagree with itself.
Run configurationThe A/B settings that governed the run.Stamped when the run was created: prompt variant (current/cached), concurrency, caching, prompt version, body limit.

Baseline: Run 1 is the reference column. Kept / Dropped / cost / time are each run's own totals (directly comparable when both ran the same shortlist); only the “disagree with Run 1” row is a like-for-like comparison restricted to the pages both runs evaluated.
